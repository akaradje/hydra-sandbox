# Strategies

When to use each sandbox strategy.

## Strategy overview

### `subprocess` (default, cross-platform)

Runs code in a child `python -c` process with:

- Import guard (blocks dangerous stdlib modules)
- Socket monkey-patching (network isolation)
- Environment sanitization (secrets purged)
- POSIX resource limits (CPU, memory, file descriptors)
- Output truncation (1 MiB cap)

**Use when**: you need a cross-platform solution and trust the Python-level
guards for your threat model. Suitable for LLM agent tools where code is
generated by a model (not submitted by an adversary).

### `seccomp` (Linux only)

Adds kernel-level syscall filtering on top of `subprocess`:

- Whitelists ~30 safe syscalls (read, write, mmap, etc.)
- Kills on `execve`, `fork`, `clone`, `socket`, `ptrace`, etc.
- Requires `libseccomp` and `pyseccomp`

**Use when**: code comes from untrusted users and you're on Linux.
Blocks `os.system()`, `os.fork()`, and any process-spawning attempt
even if the import guard is bypassed.

**Setup**:
```bash
apt install libseccomp-dev
pip install hydra-pysandbox[seccomp]
```

### `landlock` (Linux 5.13+)

Adds kernel-level filesystem access control:

- Restricts read/write to the sandbox temp directory
- Prevents reading `/etc/passwd`, writing to `/tmp`, etc.
- Requires the `landlock` Python package

**Use when**: you need to prevent filesystem escapes. Combine with
`seccomp` for comprehensive protection.

**Setup**:
```bash
pip install hydra-pysandbox[landlock]
```

### `seccomp+landlock` (strongest)

Combines both kernel-level protections:

- `seccomp`: syscall filtering (no fork, exec, socket)
- `landlock`: filesystem sandbox (no read/write outside temp dir)

**Use when**: you're running truly untrusted code on a Linux host.
This is the recommended strategy for production deployments.

### `auto` (smart default)

Detects platform capabilities at startup and picks the strongest
available strategy:

1. `seccomp+landlock` if both are available
2. `seccomp` if available
3. `subprocess` fallback

Detection is cached for the lifetime of the process.

## Checking availability

```python
from hydra_sandbox.strategies import available_strategies

print(available_strategies())
# ['subprocess', 'seccomp', 'landlock', 'seccomp+landlock']
```

Or via CLI:

```bash
hydra-pysandbox doctor
```
